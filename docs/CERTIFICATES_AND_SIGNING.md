# Samsung Tizen Security Architecture & Certificate Signing

## The Tizen Security Model
Samsung Tizen uses cryptographic signing to control platform execution and prevent unauthorized hardware access. Every application package (`.wgt` or `.tpk`) must contain:
1. `author-signature.xml`: Generated using the developer's private author certificate (`author.p12`). Validates app integrity and developer identity.
2. `signature1.xml`: Generated by Samsung's certificate server (`distributor.p12`). Enforces device whitelisting (DUID binding) and privilege tier elevation.

---

## Public vs. Partner Privilege Levels

Tizen categorizes APIs into three security tiers:

| Privilege Level | Scope & APIs | Sideload Signing Requirement |
| :--- | :--- | :--- |
| **Public** | Standard Web APIs, basic networking, LocalStorage, Canvas. | Basic Tizen Developer Certificate. |
| **Partner** | Native hardware acceleration (`avplay`), product metadata (`productinfo`), TV audio passthrough, low-latency display buffering. | **Samsung Partner Certificate** signed with registered TV DUID. |
| **Platform** | Kernel modifications, low-level OS management, firmware flasher. | Restricted to Samsung internal engineering only. |

> [!WARNING]
> High-performance streaming clients like **Moonfin** and **Moonlight** strictly require **Partner-level privileges** to invoke Samsung's `webapis.avplay` hardware decoder. Installing with a Public certificate will result in a black screen, crash on startup, or signature verification refusal (`closed by author signature` error).

## Device Unique Identifier (DUID)
To generate a valid Partner distributor certificate, you must provide your TV's **DUID**.

### Extracting DUID via SDB
Once connected via SDB (`tv-connect.sh`), query the TV serial / DUID:
```bash
sdb capability | grep -i duid
```
Output example:
```
duid: 1.0#<alphanumeric-device-id>
```

## Automated Signing via Apps2Samsung

The open-source tool `Apps2Samsung.AppImage` automates Certificate Signing Requests (CSR) with Samsung's certificate infrastructure:

1. **Launch Apps2Samsung**:
   ```bash
   ~/Downloads/samsung-tv-tools/Apps2Samsung.AppImage
   ```
2. **Device Detection**: Enter your TV's IP address (e.g., `192.168.1.100`) and click **Scan/Connect**. It automatically queries the DUID.
3. **Samsung Account Auth**:
   - Provide your Samsung Account login credentials.
   - The tool generates `author.csr` and `distributor.csr`, sends them to Samsung's server (`svdca.samsungqbe.com`), and retrieves `signed_author.cer` and `signed_distributor.cer`.
4. **Certificate Output Location**:
   Certificates are saved locally under:
   ```
   ~/.config/Apps2Samsung/Certificate/Jelly2Sams - Partner/
   ├── author.p12
   ├── distributor.p12
   ├── device-profile.xml
   └── password.txt
   ```
5. **Signing & Installation**:
   Apps2Samsung embeds the DUID into `device-profile.xml`, signs the `.wgt`, and pushes it directly through `sdb install`.
